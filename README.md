# Череда — учёт смен и табель отдела

Flutter-приложение для учёта рабочего времени. Данные хранятся на сервере
FastAPI/PostgreSQL; Excel нужен только для передачи месячного табеля руководителю.

## Работа с табелем (версия 1.1.1)

1. В графике откройте день и заполните часы и отметки сотрудников.
2. Для работы в выходной используйте «Внеплановый выход».
3. Проверьте день и закройте его. Незаполненные отметки будут заменены на
   «Неявка» только после подтверждения. Закрытие касается показанных сотрудников,
   а не чужого отдела. При необходимости переоткройте день.
4. Откройте «Табель» в меню или кнопку табеля в календаре.
5. Выберите месяц, отдел и при необходимости группу, нажмите «Сохранить Excel».
   На Windows появится диалог сохранения; на Android/iOS — меню отправки/сохранения.

| Отметка | Что попадёт в Excel | Часы в итоге |
| --- | --- | --- |
| Вышел | 11 (либо фактические часы) | Да |
| Командировка без часов | К | Нет |
| Командировка с работой | 11к | Да |
| Работа в отпуске | о 11 | Да |
| Отпуск | О | Нет |
| Больничный | Б | Нет |
| Неявка | Н | Нет |
| Без содержания | б/с | Нет |
| Не заполнено | Пустая ячейка | Нет |

При массовой отметке выхода уже заполненные отпуска и другие статусы не заменяются.
В выгрузке сохранены 57 столбцов и порядок полей образца «Табель.xlsx».
Денежные поля и телефон пустые: приложение не рассчитывает зарплату в этом отчёте.
Подсчитываются фактические часы, включая внеплановую работу и последний день месяца.
Итог под днями — количество сотрудников с положительными отработанными часами.
Дробные часы в комбинированных отметках выводятся до четырёх десятичных знаков;
итог восстанавливается до целых минут, отображается с двумя десятичными знаками.
После ручных изменений отметок надёжнее повторно сформировать файл из приложения.

Незаполненные плановые дни выделяются отдельно. Перед выгрузкой неполного табеля
появляется предупреждение; число незаполненных/незакрытых дней добавляется в примечания.
Пустая отметка не превращается в неявку просто при просмотре или экспорте.
Для табеля требуются права viewAttendance и viewEmployees; область доступа и
скрытые администратором группы проверяются сервером.

## История и обновление сервера

Нужны новая версия приложения **и** обновлённый backend. Старый сервер не имеет
эндпоинтов /api/v1/reports/month и /api/v1/reports/month.xlsx.

При запуске backend выполняется идемпотентная миграция:

- добавляются новые статусы и персональные блокировки закрытых дней;
- сохраняются исходные сведения о сотрудниках, графиках и отделах;
- ранее неявно заданные часы обычных смен фиксируются по графику на момент обновления;
- старые общие закрытия сохраняются как блокировки по сотрудникам.

Дальнейшие изменения сотрудника действуют с текущей даты, не переписывая прошлые
месячные отчёты. При переводе внутри месяца формируются отдельные строки по отделам.
Изменения, сделанные до внедрения истории, восстановить автоматически невозможно.
Экран дня использует состав отдела и график на выбранную дату, в том числе для
переведённых и уволенных сотрудников. Область доступа проверяется на эту дату;
новые отметки после увольнения не создаются, старые можно исправить.

## Исправления 1.1.1

- Изменение комментария сохраняет ранее введённые часы, пока явно не изменены
  время работы или перерыв.
- Доступ к структуре ограничен отделом/группой пользователя; общие должности
  изменяются только пользователем с общей областью доступа.
- Сброс/смена пароля и отключение аккаунта отзывают все старые сессии,
  включая одновременно обновляемые токены.
- Формы сотрудников ведут только часы и отметки, не перезаписывая денежные поля.
- Формы входа и диалоги прокручиваются при открытой клавиатуре. Исправлены
  переполнения длинных названий, крупных шрифтов, календаря, табеля, ролей
  и предпросмотра сотрудника на компьютере.

Перед обновлением рабочей установки обязательны резервная копия PostgreSQL,
проверка её восстановления и сохранение предыдущего образа API. Остановите старый
API перед миграцией; не запускайте старую и новую версии параллельно.
После миграции не запускайте старый API поверх обновлённой базы: он не знает новых
статусов и персональных блокировок. Для полного отката нужны предыдущие API и база.
Файлы развёртывания находятся в deploy/.

## Организации: 1.2.0

Одна «Череда», вход по коду организации и личным учётным данным. Для текущего
предприятия используется `tehnodor-sk` — ООО «Технодор СК». Серверы и базы
организаций изолированы; общая инструкция оператора — `deploy/ORGANIZATIONS.md`.
Новый клиент требует обновления API и шлюза. Код организации не является паролем.

## Разработка и проверки

Flutter SDK и Visual Studio с компонентами разработки C++ для сборки Windows:

```powershell
flutter pub get
flutter analyze
flutter test
flutter build windows --release
```

На Windows собирайте из пути без кириллицы, например X:/shift_tracker:
MSBuild/Flutter могут некорректно передавать кириллические пути.
Адрес API можно задать через --dart-define=SHIFT_TRACKER_API_URL=https://example.com.

Для backend нужен Python 3.11+ и PostgreSQL 17:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r backend/requirements-dev.txt
.venv/Scripts/python -m pytest backend/tests -q
```

Быстрые тесты используют изолированную SQLite-базу. Для миграции и конкурентного
закрытия дней дополнительно задайте TEST_POSTGRES_URL на отдельный локальный
PostgreSQL. Тесты создают и удаляют только свои уникальные схемы test_timesheet_*;
DATABASE_URL не используется для выбора тестовой базы. Без TEST_POSTGRES_URL
эти проверки пропускаются. Проверки организаций дополнительно запускают два API
и создают/удаляют собственные базы `test_organization_*` на этом же локальном сервере.

`test/layout_audit_test.dart` проверяет 18 экранов и 6 видов диалогов:
узкий экран 320 px, клавиатуру, горизонтальную ориентацию, шрифт до 200%
и компьютер. Данные вымышленные, HTTP подменён в памяти: тесты не обращаются
к рабочему серверу. Для PNG-проверки можно задать `LAYOUT_AUDIT_OUTPUT`,
а `LAYOUT_AUDIT_FONT` — путь к локальному TTF-шрифту (не включается в приложение).

Переменные рабочего backend: DATABASE_URL, JWT_SECRET, BOOTSTRAP_TOKEN
(описаны в deploy/.env.example). Не добавляйте рабочие секреты в репозиторий.

Вымышленный пример Excel без доступа к базе:

```powershell
.venv/Scripts/python backend/scripts/export_demo_timesheet.py ./demo.xlsx
```
