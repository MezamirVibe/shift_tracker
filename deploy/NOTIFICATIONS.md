# Уведомления «Череды»

Новые события сохраняются в базе своей организации и доступны только адресату
в рамках его текущих прав. Старые изменения не превращаются в новые уведомления.
Общий выключатель и каждый тип push можно отключить независимо. История рабочих
событий остаётся в приложении. Настройки принадлежат аккаунту, а разрешение Android
и его каналы — отдельному устройству. После выхода локальная привязка очищается.

Типы: учтённые часы/закрытие и переоткрытие дня, решение по запросу, изменение
графика, напоминание о смене, новый запрос руководителю, сводка незаполненных дней,
ошибка отправки табеля. Напоминания выключены по умолчанию: о завтрашней смене —
в 20:00, сводка за текущий месяц — в 18:00 выбранного часового пояса. За день
создаётся не более одной сводки каждого типа. Просроченные напоминания не догоняют
пользователя следующим утром. Тихие часы по умолчанию 22:00–08:00.

## Однократное подключение Firebase

Google-аккаунт нужен только владельцу Firebase-проекта, не сотрудникам.
Один проект используется всей «Чередой»; данные организаций остаются на нашем
сервере. Firebase получает токен устройства, случайные идентификаторы события
и привязки, тип уведомления — без ФИО, часов, комментариев и кода организации.

1. Создайте проект в [Firebase Console](https://console.firebase.google.com/).
   Для push не требуется подключать Google Analytics.
2. Добавьте Android-приложение с **существующим** идентификатором
   `com.example.shift_tracker`. Не меняйте пакет или ключ подписи «Череды».
3. Скачайте `google-services.json` и поместите в `android/app/google-services.json`
   на машине сборки. Этот клиентский файл не является серверным приватным ключом.
   Он не коммитится; без него сборка явно показывает, что Android-push не настроен.
4. В настройках проекта / Cloud Messaging проверьте включение FCM HTTP v1 API.
   Настройте отдельную сервисную учётную запись только для отправки FCM-сообщений
   этого проекта. Полученный приватный JSON храните как серверный секрет.
   Его нельзя отправлять в чат, включать в APK, репозиторий или публичные сборки.
5. Передайте приватный JSON защищённым каналом на сервер в
   `/opt/shift_tracker/deploy/secrets/fcm/service-account.json`.
   Каталог `deploy/secrets` должен быть приватным (0700). Вложенный каталог `fcm`
   должен быть доступен контейнерному пользователю для чтения/прохода (0755),
   файл — только для чтения (0444): на хосте его защищает родительский каталог 0700.
   В контейнер монтируется только `secrets/fcm` и только read-only, не все секреты.
6. Создайте приватный `deploy/.env.push` (0600):

   ```dotenv
   FCM_PROJECT_ID=ваш-идентификатор-проекта
   GOOGLE_APPLICATION_CREDENTIALS=/run/chereda-fcm/service-account.json
   ```

   Основной Compose и отдельные организации читают один необязательный файл;
   новые организации получают ту же доставку, сохраняя отдельные базы/очереди.
   Требуется Docker Compose с поддержкой `env_file.required` (2.24 или новее).
7. После резервной копии и проверки конфигурации обновите API. Соберите Android
   с клиентским JSON и прежней подписью. Не публикуйте тестовые ключи или заглушки.

Официальные инструкции: [подключение Android](https://firebase.google.com/docs/android/setup),
[серверная авторизация FCM HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api).

## Проверка доставки

На тестовой учётной записи реального телефона разрешите уведомления и включите
push в настройках «Череды». Используйте только согласованного тестового сотрудника,
не меняйте рабочие часы ради проверки. Проверьте открытое, свёрнутое и закрытое
приложение; переход в правильный день/запрос; каждый выключенный тип и общий
выключатель; тихие часы; выход и смену организации; отозванные права.

Android требует Google Play services и системное разрешение на уведомления.
После принудительной остановки из настроек ОС потребуется снова открыть приложение.
Доставка зависит от сети и ограничений ОС; очередь и история не являются обещанием
мгновенной доставки. Уже переданный push может оказаться в пути при изменении
настроек на другом устройстве. Текущий телефон дополнительно фильтрует отключённые
типы и прежние привязки локально.

В Windows доступна история и настройки аккаунта, но системная фоновая push-доставка
Windows в этом этапе не подключена. Отдельный значок приложения не означает,
что уведомления придут после полного закрытия Windows-приложения.

Сервис запускается и без Firebase: история доступна, настройки сохраняются,
но интерфейс должен честно сообщать, что внешняя доставка не настроена.
