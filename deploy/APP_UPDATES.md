# Публикация обновлений приложения

Клиент читает `https://api.mezamir.com/updates/stable.json`. Этот каталог содержит
только публичные APK, Windows ZIP и манифест. Базы, резервные копии, `.env` и файлы
организаций в него не помещаются. Маршруты API и организаций не меняются.

Для каждого релиза сначала собрать APK с прежним сертификатом/идентификатором и
Windows ZIP с приложением в корне архива, проверить их и записать размер и SHA-256.
Номер `build` должен увеличиваться. В каждой платформе манифеста обязательны поля
`version`, `build`, `url`, `sha256`, `size`, `notes`; верхний уровень —
`{"schema": 1, "android": {...}, "windows": {...}}`. `notes` — список строк.

Пакет можно подготовить командой `python tool/package_app_update.py --apk APK
--windows ZIP --output НОВЫЙ_КАТАЛОГ --version 1.7.0 --build 13 --note "Описание"`.
Скрипт создаёт имена файлов, SHA-256, JSON и tar.gz. Сертификат APK и версии
исполняемых файлов необходимо проверить до упаковки. Не перепубликовывать иной
бинарный файл под существующей версией.

## Как работает клиент

Версия 1.7.0 — первая с обновлением внутри приложения. Её один раз устанавливают
вручную поверх прежней версии, без удаления приложения. Дальше клиент проверяет
манифест при запуске, при возврате (не чаще раза в 6 часов) и вручную в настройках.
Загрузка начинается только по кнопке; можно отменить её или продолжить работу.
Отдельный HTTPS-клиент не передаёт токены и код организации. Файл проверяется по
размеру и SHA-256, переходы на другие адреса запрещены.

Android дополнительно сверяет пакет, подпись и номер сборки. При необходимости
пользователь разрешает установку для «Череды», возвращается и повторно нажимает
«Установить». Окончательное подтверждение всегда выполняет Android.

Windows перед закрытием проверяет архив, версию EXE и папку установки. Помощник
не заменяет файлы без отдельного сигнала COMMIT от приложения. Он не завершает
процессы принудительно, сохраняет резервные копии заменяемых файлов и откатывает
ошибки копирования. Требуются права записи в папку приложения; повышения прав нет.
Базы и пользовательский AppData не затрагиваются. Во время подготовки установки
новые API-запросы заблокированы, незавершённые сохранения не прерываются.

Резервные копии Windows остаются в уникальном каталоге `TEMP/chereda-update-*`,
его адрес есть в журнале. Сбой питания непосредственно при замене файлов может
потребовать ручного восстановления этой копии. Публикуются полные сборки,
дельта-обновления и автоматическая установка без согласия не используются.

## Публикация на сервере

Архив публикации `tar.gz` должен содержать **ровно три обычных файла**, без отдельных
записей каталогов и символьных ссылок:

```text
stable.json
1.7.0/Chereda-1.7.0-android.apk
1.7.0/Chereda-1.7.0-windows.zip
```

Загрузить архив и `publish-app-update.py` в `/tmp`, затем запустить на сервере:

```sh
python3 /tmp/publish-app-update.py \
  --archive /tmp/app-updates-1.7.0.tar.gz \
  --sha256 SHA256_АРХИВА \
  --version 1.7.0 --build 13 \
  --release app-updates-1.7.0-20260923
```

Скрипт сохраняет текущие конфигурации, делает и проверяет полные резервные копии
баз всех действующих организаций, сравнивает содержимое всех публичных таблиц.
Материалы проверки и дампы остаются приватными в
`/opt/shift_tracker/releases/ИМЯ_РЕЛИЗА/`. API, PostgreSQL, схема и данные не меняются.
При первом подключении публичного каталога пересоздаётся только Caddy; последующие
публикации обходятся без его перезапуска. Перед изменением валидируются текущая
конфигурация с точечной вставкой и Docker Compose. Несовпадающая/неоднозначная
конфигурация требует ручной проверки.

Версионные файлы неизменяемы: повторная публикация той же версии допустима только
при совпадении хешей. Манифест переключается атомарно после проверки обоих URL.
Он не кешируется; версионные файлы кешируются как неизменяемые.

При ошибке включения восстанавливаются только конфигурация Caddy/Compose и прежний
манифест. База **никогда не восстанавливается автоматически**. Если сотрудники
изменили данные во время публикации, итоговый отчёт укажет отличия снимков; их нужно
сверить, а не стирать новые записи. Не переиспользовать имя каталога уже начатого
релиза: для повторной попытки выбрать новый `--release`.
