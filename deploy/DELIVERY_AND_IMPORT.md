# Череда 1.3: QR, импорт и отправка

## Подключение организации

На экране подключения больше нет примера действующей организации. Можно сканировать
QR камерой (Android/iOS), выбрать PNG/JPEG или вставить ссылку/код. QR находится
в «Настройки → Подключить другое устройство». Он содержит только селектор организации,
не пароль и не сессию. После подключения обязательны личные логин и пароль.
Адрес сервера из QR не принимается. Внутренний код организации и JWT audience не меняются.

## Импорт

«Табель → Действия с табелем → Импортировать старый табель» или раздел сотрудников.
Поддерживается .xlsx до 3 МБ, до 500 сотрудников, одна строка на сотрудника,
заголовки ФИО и последовательность дней 1–28/29/30/31. Лист выбирается явно, если их несколько.
Период выбирается пользователем и сверяется с названием листа вида MM.YYYY.
Копия исходного образца «Табель.xlsx» с пустыми ФИО — шаблон, а не источник сотрудников.

Переносятся ФИО, должность, часы и отметки. Финансовые поля не читаются.
К/11к, О/о 11, Б, Н, б/с поддерживаются; формулы в ФИО и отметках отвергаются,
не вычисляются и не заменяются недостоверными кешированными результатами.
Архивы ограничиваются по распакованному размеру, XML-сущности запрещены.

Предпросмотр не меняет базу. Строки нужно выбрать и подтвердить отдельно.
Совпадение активного сотрудника по полному нормализованному ФИО видно до подтверждения.
Неоднозначные имена блокируются. Архивные однофамильцы не восстанавливаются автоматически:
предпросмотр предупреждает о создании отдельного нового сотрудника.
Существующие несовпадающие отметки и закрытые дни сохраняются, конфликты показаны счётчиком.
Изменения после предпросмотра требуют повторной проверки; повторный запрос не создаёт дубликаты.
График новых сотрудников выбирается отдельно (по умолчанию 5/2, 9 ч с перерывом 1 ч),
начало — первое число импортируемого месяца. По фактическим часам график не угадывается.

## Telegram: настройка оператором

Для каждой изолированной организации нужен отдельный бот, выделенный только Череде.
Общий токен для нескольких инстансов не поддерживается. Webhook у бота должен быть выключен;
используется getUpdates. Не подключайте существующего бота другой системы без согласования.

В приватный env-файл организации (права 0600) оператор добавляет:

```
TELEGRAM_BOT_TOKEN=<секретный токен от BotFather>
TELEGRAM_BOT_USERNAME=<имя без @>
```

Пересоздать только API-контейнер соответствующей организации. Не хранить токен в Git,
мобильном приложении, скриншотах или переписке. Без обоих параметров worker выключен.

Пользователь: «Табель → Действия с табелем → Отправка по расписанию».
Создать ссылку, открыть её в личном чате либо группе, нажать «Запустить» и вернуться
в приложение. Ссылка одноразовая, действует 10 минут. Для группы требуется её администратор.
Приложение показывает имя и ID найденного чата: пользователь подтверждает получателя,
затем отдельно включает расписание с подтверждением передачи персональных данных в Telegram.
Смена получателя отключает прежнее расписание. Денежные поля в файле пустые.

Ежедневное, еженедельное или ежемесячное расписание (число 1–28), время и часовой пояс IANA,
текущий/предыдущий месяц и доступные отдел/группа. Незаполненные либо незакрытые дни
по умолчанию запрещают отправку. Можно явно разрешить незавершённый табель.
В подтверждённом чате подключивший его Telegram-пользователь может использовать:
`/time 09:30`, `/pause`, `/status`. Время не включает выключенное расписание.
При нескольких настройках одного отправителя/чата изменение доступно только в приложении.

Права владельца заново проверяются перед каждым отправлением. База/получатели изолированы
по организации. Очередь хранится в PostgreSQL. Каждая запланированная отправка резервируется
до сетевого вызова; несколько процессов не отправляют один файл повторно.
При неопределённом результате сети либо сбое процесса автоповтора нет: нужно проверить чат.
Задержка после простоя более двух часов пропускается, старые файлы пачкой не отправляются.
Результат/ошибка видны в приложении. Ручная отправка доступна через «Поделиться табелем».

## Проверки и ограничения выпуска

Автотесты покрывают импорт, права, повторы, конкуренцию PostgreSQL, QR из изображения,
расписание и передачу файла через тестовый транспорт. Реальная камера телефона и реальная
доставка Telegram требуют проверки после установки/подключения бота. Тесты не отправляют
данные пользователей внешним получателям. Секреты и содержимое Telegram-обновлений не логируются.
